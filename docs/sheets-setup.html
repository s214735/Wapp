ONE-TIME SETUP

Connect your graphs

Keep your spreadsheet private. Google sign-in lets Wapp read the file you select.

You need three values from the same Google Cloud project: an OAuth client ID, a Picker API key, and the project number. You do not need a client secret. Enter these in Wapp on each device you use.

  1. Create a project. Open the Google Cloud console using your personal Google account. Create a project named Wapp. Copy its numeric Project number from the project dashboard or IAM & Admin → Settings.
  2. Enable three APIs. Under APIs & Services → Library, find and enable Google Sheets API, Google Drive API, and Google Picker API.
  3. Set up Google Auth Platform. Name the app Wapp, select your support/contact email, and choose an External audience. For initial personal testing, keep the app in Testing and add your own Google account as a test user. Under Data Access, add only this scope:
    https://www.googleapis.com/auth/drive.file
    This limits access to files selected for Wapp. Google describes it as permission to view and edit those files; Wapp currently sends only read requests. Testing-mode grants may expire and require reconnecting. Before broader distribution, review Google's publishing and verification requirements.
  4. Create the OAuth client. Under Google Auth Platform → Clients, choose Create client → Web application. Add this exact Authorized JavaScript origin:
    https://s214735.github.io
    Do not include /Wapp/. This browser popup flow needs no redirect URI. Copy the client ID ending in .apps.googleusercontent.com. Keep any client secret out of Wapp.
  5. Create a Picker API key. Under APIs & Services → Credentials, create an API key. Edit it: set application restrictions to Websites, and allow:
    https://s214735.github.io/*
https://docs.google.com/*
    Google's picker runs inside a docs.google.com frame, so both are needed. Set API restrictions to Google Picker API and Google Drive API. Copy the key.
  6. Save the connection in Wapp. Open Settings → Data. Paste your private spreadsheet link. Use O-MF and O-V as the chart sheet names (spelling and capitalization must match). Expand Google connection setup and paste the three values. Tap Save spreadsheet settings.
  7. Connect. Open Data → Connect with Google. Sign in to the account that owns the file, review Google's permission request, and select that same spreadsheet in the file picker. Wapp reads its chart definitions and source cells, then draws the graphs. If Google sign-in is blocked in the home-screen app, try Wapp in Safari.

What is saved?

The link, chart sheet names and connection configuration stay in this browser. Access tokens and graph data stay in memory only; they are not included in backups or app-file caches. Reloading requires connecting again. Refresh gets the latest spreadsheet values. Disconnect clears the displayed graphs and access token on this device. To revoke Google's saved authorization entirely, use your Google account connections.

Troubleshooting

  • Origin mismatch: check the Authorized JavaScript origin exactly, without a path or trailing slash.
  • Access blocked: check that your account is a test user and all three APIs are enabled in the same project.
  • Invalid developer key: check the key restrictions, including https://docs.google.com/*, and that the project number matches the client ID's project.
  • File not accessible: select the exact spreadsheet saved in Settings, using the Google account that can read it.
  • Missing chart: check the tab names and that each selected tab actually contains a chart.
  • Expired connection: tap Connect with Google again. Expiry does not change your spreadsheet.

Graphs are recreated from source cells, not embedded screenshots. Standard line, area, bar, column, scatter, combo and pie charts are supported. Complex or aggregated charts can show an explicit unsupported message; formatting may differ from Sheets.
